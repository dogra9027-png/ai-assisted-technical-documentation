# Nexus IT Operations Platform
## Terminology Glossary

**Document Type:** Terminology Reference  
**Version:** 1.0  
**Status:** Portfolio Demonstration

---

## 1. Purpose

This glossary defines the approved terminology used throughout Nexus IT Operations Platform documentation.

It helps maintain consistent language across user guides, administrator documentation, technical references, troubleshooting articles, and training materials.

## 2. Product and Platform Terms

| Term | Definition | Usage Guidance |
|---|---|---|
| Nexus | Short name for Nexus IT Operations Platform | Use after introducing the full product name. |
| Platform | The Nexus web-based application | Use when referring to the application as a whole. |
| Dashboard | A visual summary of infrastructure and operational information | Use consistently for the main dashboard. |
| Infrastructure | Servers and other IT components monitored by Nexus | Do not use interchangeably with the platform. |

## 3. Monitoring Terms

| Term | Definition | Usage Guidance |
|---|---|---|
| Infrastructure monitoring | Monitoring the health and availability of IT components | Use when describing monitoring functionality. |
| Server | A monitored computing system | Use for an individual server. |
| CPU utilization | The percentage of processor capacity in use | Use when describing processor metrics. |
| Memory utilization | The amount of memory currently in use | Use when describing memory metrics. |
| Storage utilization | The amount of storage capacity currently in use | Use when describing storage metrics. |
| Health status | The reported operational condition of a monitored component | Use when describing infrastructure condition. |

## 4. Alert Management Terms

| Term | Definition | Usage Guidance |
|---|---|---|
| Alert | A notification generated when a monitored condition requires attention | Preferred term for an alert record. |
| Alert severity | The urgency level assigned to an alert | Use Critical, High, Medium, or Low. |
| Active | An alert that has been generated and requires review | Use as a defined alert status. |
| Acknowledged | An alert that an authorized user has reviewed | Do not use as a synonym for resolved. |
| Resolved | An alert whose underlying condition has been addressed | Use as a defined alert status. |
| Acknowledge | To mark an alert as reviewed | Use as a verb for the user action. |

## 5. Incident Management Terms

| Term | Definition | Usage Guidance |
|---|---|---|
| Incident | A recorded operational issue requiring investigation or resolution | Use instead of ticket or problem when referring to a Nexus incident. |
| Priority | The classification indicating the urgency of an incident | Use when discussing incident handling. |
| Assignment | The allocation of an incident to a responsible team member | Use when describing incident ownership. |
| Resolution notes | Information documenting how an incident was addressed | Use when describing incident closure details. |
| Open | An incident that requires investigation | Defined incident status. |
| In Progress | An incident currently being investigated or addressed | Defined incident status. |
| Closed | An incident formally closed after review | Defined incident status. |

## 6. User and Access Management Terms

| Term | Definition | Usage Guidance |
|---|---|---|
| Administrator | A user authorized to manage accounts, roles, and monitoring settings | Use the full term in formal documentation. |
| Operations Analyst | A user responsible for monitoring infrastructure and investigating alerts and incidents | Use as the defined role name. |
| Viewer | A user with permission to view dashboards and reports | Use as the defined role name. |
| Role | A collection of permissions assigned to a user | Use when describing access control. |
| Permission | Authorization to perform a specific action or access a feature | Do not use interchangeably with role. |
| Role-based access control (RBAC) | An approach that grants permissions according to assigned roles | Define the abbreviation on first use. |
| Deactivate | To disable a user account | Use instead of delete when referring to account deactivation. |

## 7. User Interface Terms

| Term | Definition | Usage Guidance |
|---|---|---|
| Sign in | The process of accessing Nexus using assigned credentials | Use as a verb. |
| Sign out | The process of ending an authenticated session | Use as a verb. |
| Select | An action used to choose an interface item | Preferred instructional verb. |
| Filter | A control used to narrow displayed information | Use when describing list filtering. |
| Status | The current state of an alert or incident | Identify the relevant record type. |

## 8. Approved Writing Conventions

| Preferred | Avoid |
|---|---|
| Sign in | Login (as a verb) |
| Sign out | Logout (as a verb) |
| Acknowledge an alert | Accept an alert |
| Resolved | Fixed (as a formal status) |
| Administrator | Admin |
| Select | Click (unless the interaction specifically requires a mouse click) |
| User account | User profile (when referring to account access) |

## 9. Acronyms

| Acronym | Full Form |

| IT | Information Technology |

Review this glossary whenever product features, user roles, interface labels, or documentation terminology change.

New terms must be defined before being introduced into published documentation.
